# Writing docs pages (for every contributor, human or agent)

Site: Astro + Starlight in `site/`. Pages live in `src/content/docs/<section>/<slug>.mdx`, URL `/<section>/<slug>/`.
Sections: start, concepts, guides, migration, reference. (The `api/` folder is generated by TypeDoc: never edit it.)
Source of truth: the library in `../src/*.ts` (read it!) and the tests in `../test/*.test.ts` (verified behaviour).
`../examples/*.ts` and `~/new-projects/nodelibraries-ioc/docs/` are written for the OLD package `@nodelibraries/ioc`:
use them for topics and ideas, never copy claims without checking them against `../src`.
Never document something you didn't verify in the source.

## Audience and tone
Engineers wiring up a TypeScript or Node app. Short, concrete, code-first. Lead with what it's for and when to use it, then code.
No marketing fluff, no "simply", no emoji in prose. English. Sentences short. Explain *why* behind defaults.
Mention the .NET equivalent where it helps (`AddSingleton`, `IServiceScope`, `ValidateScopes`), never require .NET knowledge.

## Code blocks
- Use ```` ```ts twoslash ```` for TypeScript examples that import `'@ylcnfrht/ioc'`: they are TYPE-CHECKED at build time
  against the real source. A type error fails the build, so examples must compile. Declare external things you use but
  don't define (`declare function sendMail(to: string): Promise<void>;`) and put scaffolding above `// ---cut---` to hide it.
  Top-level `await` and `await using` work.
- To show a deliberate compile error use `// @errors: 2345` (the TS error code) above the cut. The build fails on an unexpected error, but NOT if the expected one doesn't happen: check the rendered output.
- Show types on hover with `//    ^?` sparingly (one per page max), only where the inferred type is the point.
- Plain ```` ```ts ```` (no twoslash) only for snippets that can't compile standalone (Express/Fastify/Nest apps needing
  packages not installed in `site/`). ```` ```js ```` for JavaScript. Shell: ```` ```sh ````. Titles: ```` ```ts title="app.ts" ````.
- Known type gotcha: `getRequiredService<string>('apiUrl')` resolves to `unknown` (a `string` type argument matches the
  `K extends Token` overload). Use `createToken<string>('ApiUrl')` for values instead and say so where relevant.

## Links
Internal links are absolute without domain: `/concepts/lifetimes/`. API reference pages live under `/api/...`
(e.g. `/api/classes/servicecollection/`, `/api/classes/serviceprovider/`, `/api/functions/createtoken/`,
`/api/classes/circulardependencyerror/`). Only link pages that exist or are listed below; the build validates links.

## Build
```sh
cd site && SKIP_TYPEDOC=1 SKIP_LINKS=1 ASTRO_OUT_DIR=<scratch>/dist ASTRO_CACHE_DIR=<scratch>/cache npx astro build
```
Use your own scratch dirs when others build at the same time. It must end with `Complete!`. The full build
(`npm run build`) also generates the API pages and checks every link.
